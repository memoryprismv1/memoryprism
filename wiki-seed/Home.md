# Memory Prism Wiki

**A structural framework for understanding persistence under constraint.**

Memory Prism helps enter unfamiliar topics by examining the conditions under which things form, move, persist, change, and fail. It is an entry point for inquiry—not an exhaustive protocol or a substitute for domain knowledge.

Canonical framework: [Memory Prism v1.0 — DOI 10.5281/zenodo.19287268](https://doi.org/10.5281/zenodo.19287268). See the [About page](https://www.memoryprism.com/about), [source index](https://github.com/memoryprismv1/memoryprism/blob/main/SOURCES.md), and [licence statement](https://github.com/memoryprismv1/memoryprism/blob/main/LICENSE.md).

## The starter route

**Observation → Conditions → Movement and persistence → Change or uncertainty → Better next question**

This is a flexible route, not a mandatory sequence. Skip any part that adds no value, and follow the domain-specific question that becomes most interesting.

## Core rule

The checklist should improve the next question, not make every answer look like Memory Prism. Answer settled questions directly. Keep evidence distinct from inference. Let each lens earn its keep.

Source: the Memory Prism Framework and exactly seven supporting essays: Boards, Audits, Identity, Flow Under Constraint, Working Lines, No Sacred States, and Accumulation Patterns.
