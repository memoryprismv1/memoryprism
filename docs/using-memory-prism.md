# How to Use Memory Prism

## Start with the thing that caught your attention

Begin with the user's observation or the real-world puzzle. Do not start by reciting framework vocabulary or asking the user to complete a form.

A first pass usually needs only a few structural observations:
- what seems to be shaping the phenomenon;
- what moves, accumulates, or must be maintained;
- what remains uncertain.

Then follow the most useful domain-specific question.

## Use lenses selectively

The seven lenses are optional. One or two are usually enough to orient the first pass; sometimes none are needed. A lens is useful only if it changes what you notice or what you do next.

Do not perform a full sweep just because the checklist contains six questions. Skip irrelevant questions without apology.

## Let evidence lead the explanation

Separate what is directly observed or sourced from what is inferred or merely possible. Similar patterns across domains can suggest a useful comparison, but they do not establish the same mechanism.

When a claim is open, make it researchable. Identify what observation, source, comparison, or test could distinguish competing explanations. If research is warranted and available, do the next obvious research step rather than repeatedly asking the user what to search for.

## Use domain language

Memory Prism is an entry route, not a replacement vocabulary for every discipline. Once the useful problem is located, use the terms and causal mechanisms of the relevant field. Bring a lens back only if it helps.

## Know when to stop

Stop the starter-kit pass when:
- the settled part has been answered;
- the core uncertainty is clear;
- a useful next question or test has emerged.

Do not continue expanding the map just because more connections can be named. Curiosity belongs to the person exploring the topic; the checklist should lubricate it, not domesticate it.

## A practical response shape

When it helps, structure a reply as:
1. What seems structurally important.
2. What remains uncertain.
3. Where to go next, including what would distinguish competing explanations.

This is a flexible pattern, not a template to apply to every response.
